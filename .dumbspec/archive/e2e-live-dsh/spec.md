# e2e-live-dsh — спецификация: независимый инстанс dsh с чистыми настройками

Исходный запрос и уточнения — [draft.md](./draft.md); факты — [research.md](./research.md).

## Цель

Инфраструктура для e2e-тестирования плагина `dsh-model-settings` на живом `dsh web`:
одной командой запустить **независимый** инстанс с **чистыми настройками** и установленным
нашим плагином, и одной командой остановить его. Конкретные e2e-проверки — на стороне
пользователя; мы даём сам инстанс (ready = живой URL).

## Ограничения (из research)

- «Независимый» = отдельный `DSH_HOME` + `DSH_AGENTS_HOME` во временном каталоге,
  `cwd` процесса — тот же временный каталог (сессии и `.env` CLI живут от него).
  Настоящий `~/.dsh` не читается на запись вообще.
- Ключи провайдеров (`DEEPSEEK_API_KEY`, `URABE_API_KEY`, …) берутся из окружения
  запускающего шелла — чистый хом их не хранит.
- Плагин в инстансе = то же самое, что в живом профиле: `web`-профиль
  (автоинициализируется из шаблона base + web-app) + `dsh plugin --profile web add`
  нашего пакета как `link:`-зависимость.
- Живой инстанс пользователя на 3080 и его `~/.dsh` не затрагиваются:
  другой хом, другой порт, другой cwd.

## Решение

Один скрипт на Node (без новых зависимостей) внутри пакета:
`packages/dsh-model-settings/scripts/e2e-live.mjs`, запускается из пакета:

```
pnpm e2e:live            # порт 3081
pnpm e2e:live -- --port 3100
pnpm e2e:live -- --keep  # не удалять temp-каталог при остановке (отладка e2e)
```

### Поведение (up)

1. **Проверка артефактов**: `lib/index.js` и `lib/client.js` должны существовать.
   Если нет — явная ошибка «сначала `pnpm build`» (авто-сборки нет, по решению).
2. **Чистый мир**: `mkdtemp` корня `dsh-e2e-<rand>`; `DSH_HOME=.dsh`,
   `DSH_AGENTS_HOME=.agents`, `cwd` дочернего процесса = корень.
3. **Докинуть зависимость**: `dsh plugin --profile web add <абсолютный путь до пакета>`
   с `DSH_HOME` на чистый хом — создаёт `web`-профиль (base + web-app) и линкует пакет
   (локальный `link:`, без allowBuilds, без сети).
4. **Запуск**: `dsh web --port <порт>`; **по умолчанию 3081**, переопределяется
   `--port`. Порт занят → явная ошибка (конфликт с самим собой), не silent-skip.
5. **Ready**: из stdout/stderr дочитываем строку `dsh web: http://…` (таймаут 90 c),
   затем `GET <url>` → 200.
6. **Вывод**: URL инстанса, путь к временному корню. Скрипт остаётся на переднем
   плане и держит дочерний процесс. Проверок плагина (RPC/UI) внутри скрипта нет —
   это проверки на стороне e2e.

### Поведение (down)

- SIGINT/SIGTERM (Ctrl+C) → `SIGTERM` дочернему `dsh web` (graceful drain, exit 0),
  ожидание выхода, удаление временного корня.
- `--keep`: временный корень НЕ удаляется (путь печатается) — для отладки e2e-проверок.
- Сбой на любом шаге (артефакты, `plugin add`, ready, занятый порт) → явная ошибка с
  причиной, non-zero exit, дочерний процесс убивается; temp-каталог при `--keep`
  остаётся, без него удаляется.

### Гарантии

- Повторный запуск после Ctrl+C не оставляет мусора; живые 3080/`~/.dsh` чисты.
- Если `dsh`/`pnpm` не на PATH — явная ошибка с текстом причины.

### Границы (не входит)

- Сами e2e-проверки (UI/RPC-сценарии) — на стороне пользователя; скрипт не делает
  браузерных сценариев и не ставит playwright.
- CI, параллельные инстансы, headless-режимы, публикация плагина в npm.

## Критерии приёмки

1. `pnpm e2e:live` из `packages/dsh-model-settings` запускает `dsh web` с чистым хомом
   в temp-каталоге; настоящий `~/.dsh` неизменён (сравнение до/после).
2. В stdout печатается `http://127.0.0.1:3081` (или переданный `--port`); `GET` → 200.
3. Pлагин «докатан» в чистый профиль: `dsh --profile web --dump-config` на чистом
   хомах показывает слой `@apkawa/dsh-model-settings` (верифицируется при реализации;
   в браузере видно по секции Model settings — на стороне e2e-проверок).
4. Ctrl+C → дочерний процесс остановлен, temp-каталог удалён (кроме `--keep`).
5. Повторный запуск на тот же занятый порт → явная ошибка, живой инстанс 3080 не тронут.

## Решённые на ревью

- **Q1. Порт по умолчанию** — **3081** (фиксированный); повторный запуск на занятый
  порт — явная ошибка.
- **Q2. Авто-сборка** — **нет**: скрипт проверяет `lib/` и при отсутствии даёт
  инструкцию `pnpm build`.
- **Q3. Локация** — **внутри пакета**: `packages/dsh-model-settings/scripts/e2e-live.mjs`
  + script `e2e:live` в `packages/dsh-model-settings/package.json`.
- **Q4. Самопроверка `listModels`** — **нет**: скрипт не вызывает RPC; только ready
  (строка `dsh web: …` + HTTP 200).
