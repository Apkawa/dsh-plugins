# 2026-10-13_responsive-ui: более отзывчивый интерфейс плагина dsh-ghl

**Created:** 2026-10-13T14:55:00+03:00

## Scope

В скоуп:
- клиентская половина `dsh-ghl` (`packages/dsh-ghl/src/client`);
- in-flight состояние в сторе: загрузка списка ишью (`refresh`) и загрузка детального ишью (`select`) — флаги выставляются перед RPC и сбрасываются при завершении (и успех, и ошибка);
- UI: спиннеры через существующий общий примитив `StateDot` (`state="ongoing"`) из `@deepseek-ai/dsh-client-ui-primitives` (уже в externals tsdown-конфига плагина);
- юнит-тесты новых состояний стора (fake RPC, без jsdom — как в существующих тестах).

Не в скоуп:
- ускорение бэкенда/API (кэш хоста, сам GitHub API);
- новая e2e-инфраструктура для симуляции медленного API (приёмка рендера — typecheck + юнит-тесты + ручной прогон в браузере через `e2e:live`);
- компонентные рендер-тесты с jsdom (в пакете нет jsdom, конвенция — юнит-тесты стора + playwright e2e);
- другие плагины репозитория.

## Approach

- **Стор** (`client/index.ts`): добавить в `state` флаги `listLoading` / `issueLoading` (+ геттеры). `refresh` выставляет `listLoading` перед RPC и сбрасывает в `finally` (успех/ошибка); `select` — аналогично `issueLoading`. Ошибки по-прежнему уходят в `state.error`, как сейчас.
- **`IssuePane`**:
  - первичная загрузка (список пуст + `listLoading`) — блок загрузки «Loading issues…» (StateDot + текст) вместо пустой области;
  - обновление существующего списка (`listLoading` при непустом списке) — спиннер в/рядом с Refresh-кнопкой; локальный `refreshing`-стейт из `IssuePane.tsx:29–34` заменяется флагом из стора;
  - выбор ишью (клик по строке, `issueLoading`) — блок «Loading issue #N…» в месте детального вида; при ошибке — существующий error-блок (выбор сохраняется, как сейчас).
- **Зависимость**: добавить `@deepseek-ai/dsh-client-ui-primitives` в зависимости пакета (bundle-механика уже готова — specifier в `PLATFORM_MODULES` externals, `tsdown.config.ts:11–20`). `LoadingIndicator` из `ui-sidebar-documentpreview` использовать нельзя — это feature-плагин, и по правилам экспорта dsh feature-плагин не может импортировать другой feature-плагин.
- **CSS** (`issue-pane.module.css`): блоки загрузки в существующей стилистике (`--dsw-alias-*` токены, 12/18 caption), `data-testid`-хуки в стиле остальных (`ghl-loading-list`, `ghl-loading-issue`, …).

## Constraints

- React 18, tsdown → один CJS-бандл, CSS Modules (lightningcss), монтирование в web-shell dsh через slots.
- Клиент не делает `fetch` напрямую: `connection.rpc.call('/ghl', …)` по Cordis-соединению; хост-роут `/ghl` на `webServer`.
- В пакете нет jsdom; юнит-тесты — vitest `node` + fake RPC через `setRpc`.
- UI-конвенции плагина: цвета только через `--dsw-alias-*`, `data-testid`-хуки, ghost-капсулы для кнопок.
- Общий спиннер-примитив — `StateDot` из `ui-primitives` (единственный допустимый общий дом для UI-примитивов dsh).
- TDD (красный тест → зелёная реализация), KISS, не вводить зависимости сверх заявленных peer/dep.

## Open questions

- none — все вопросы draft закрыты исследованием (см. [research.md](./research.md)):
  - переиспользуемый спиннер есть — `StateDot` из `ui-primitives`;
  - API-взаимодействий ровно два — `refresh` (список) и `select` (деталь);
  - спиннер: блок загрузки для первичной загрузки/детали, инлайн-спиннер для обновления списка;
  - ошибки — отдельный существующий error-блок, флаги загрузки сбрасываются и в `finally`.
