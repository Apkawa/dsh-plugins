## Scope
- Проверить работоспособность поиска `packages/dsh-web-search-ddgs` тестами: прогнать unit- и e2e-тесты, зафиксировать состояние.
- Установить, какие бекенды ddgs (duckduckgo, bing, yandex) работают, а какие нет — по факту (тесты/запросы), с фиксацией результата в коде/доках.
- Уточнить и задокументировать, как правильно заменить бекенд поиска в dsh 0.2.0 (профильная замена `searchProvider`, registration seam).
- Проверить интеграционные (e2e) тесты пакета на 0.2.0-rc.2.
- Актуализировать документацию пакета (README/AGENTS) с учётом фактов.

Out of scope:
- Рефакторинг ядра поиска (кроме минимальных правок, вытекающих из фактов исследования).
- Изменения в самом dsh / upstream.
- Новый fetch-провайдер и клиентский UI (MVP остаётся MVP).

## Approach
1. Прогнать существующие тесты (unit + e2e) и зафиксировать состояние: что падает, что проходит.
2. Прогнать/дописать тесты по бекендам ddgs (duckduckgo, bing, yandex): пометить работающие и неработающие бекенды; yandex-путь (monkey-patch `ENGINES['text']['yandex']`) покрыть тестом.
3. На основе исследования dsh 0.2.0-rc.2 (seam `ctx.web`, выбор `searchProvider`) задокументировать правильный способ замены бекенда: регистрация через `registerSearchProvider` + профильный патч `searchProvider: ddgs` (config бьёт env).
4. Исправить/дописать e2e-тесты пакета (boot-матрица + live-search) так, чтобы они отражали реальное состояние; при необходимости — зафиксировать ограничения (например, отсутствие RPC-лейна).
5. Обновить README/AGENTS/доки пакета: фактические бекенды, способ замены, состояние тестов, устранение устаревших формулировок (yandex-описание в package.json и т.п.).

## Constraints
- frozen pnpm install; e2e — изолированный `DSH_HOME`, версии dsh из `E2E_DSH_VERSIONS` (0.2.0-rc.2, уже provisioned в `.tmp/dsh-versions/`).
- Тесты — TDD, unit-тесты — без сети (doubles); live-search — с сетью, self-skip без `uv`.
- Коммиты — Conventional Commits, по одному на стадию; ветку `2026-10-03_web-search-ddgs-audit` не трогать (не создавать/переключать).
- `uv` есть в PATH (`/home/apkawa/.local/bin/uv`).
- Ключевой факт: seam `WebSearchProvider` в 0.2.0-rc.2 **не изменился** относительно 0.1.2-rc.1 (byte-identical types); изменилось поведение host RPC-канала (broken host-side) — влияет на e2e, но не на сам поиск.
