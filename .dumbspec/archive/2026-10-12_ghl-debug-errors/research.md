# 2026-10-12_ghl-debug-errors: research

Task context: make the `dsh-ghl` plugin surface API errors transparently (instead of `repo: null` / "No GitHub repository detected for this workspace") and add debug logging (pattern from `packages/dsh-model-settings`); the GitHub token must not be required (free unauthenticated limits when absent).

## Findings

(appended as research progresses)

## R1 — dsh-ghl: repo detection + token handling (packages/dsh-ghl)

- **Repo detection** (`src/repo.ts`):
  - `gitRemoteUrl()` (`repo.ts:16-23`) shells out `git remote get-url origin` **in the host process's working tree** (inherited CWD — no workspace path is passed in). Resolves `null` on any git error (no git binary / not a git repo / no `origin` remote) or empty output.
  - `detectRepo(getRemoteUrl)` (`repo.ts:33-37`) → `parseGithubRemote(url)` (`repo.ts:26-30`): `parseScp()` matches `^git@github\.com:([^/]+)/([^/]+)`, `parseUrl()` requires `hostname === 'github.com'` and ≥2 path segments; both strip trailing `.git`. Anything else → `null`.
  - Wiring: `index.ts:37-40` `getRepo = async () => detectRepo(() => await gitRemoteUrl())`.
  - RPC (`rpc.ts:158-170`): `detectRepo` endpoint **always** returns `{ ok: true, value: { repo: <RepoRef|null> } }` — no error surfaced. `listIssues`/`getIssue` with null repo → `rpcFailure('no-repo', 'no GitHub repository detected for this workspace', {})`.
- **Token**: there is **no token handling anywhere** in the package (no settings/env/file read, no `Authorization` header). `GitHubIssue.request()` (`src/issues.ts:83-90`) calls `https://api.github.com…` **unauthenticated** by design; anonymous 60-req/h limit is enforced locally by `src/cache.ts` (sliding-window budget `DEFAULT_BUDGET = 60`, `WINDOW_MS = 1 h`; `guard()` throws `RateLimitError(429)` when full). User's "we wait for a token" suspicion is not backed by the code — no token path exists.
- **HTTP error mapping** (`src/issues.ts:83-90`): 403/429 → `RateLimitError`, 404 → `IssueNotFoundError`, other non-ok → `Error("GitHub API HTTP <status> for <path>")`. In `rpc.ts:180-181`: `IssueNotFoundError` → code `not-found`, `RateLimitError` → code `rate-limit` with `error.message`; other errors → `internal`.
- **Key structural fact:** `gitRemoteUrl()` inherits the dsh **host process CWD**, not the workspace directory. If the host process was started outside the workspace (or the workspace root differs from CWD), `git remote get-url origin` fails → `repo: null` even for a valid workspace. This is the leading hypothesis for the user's `repo: null` (to be confirmed in the client-side research).
- **Package orientation:** Cordis plugin `@apkawa/dsh-ghl`, host + client halves. Host: `src/index.ts` (composition root, mounts `/ghl` prefix on host `webServer` via nested `ctx.inject(['webServer'], …)`), `src/issues.ts` (`BaseIssue`, `GitHubIssue` over injected `Fetcher`), `src/repo.ts`, `src/cache.ts` (TTL 5 min / 60 s negative + budget), `src/rpc.ts` (endpoints `detectRepo`/`listIssues`/`getIssue`; failure codes `gateway`/`bad-request`/`no-repo`/`not-found`/`rate-limit`/`internal`). Client: `src/client/index.ts` (binds issue snapshot store to `/ghl`, registers right-sidebar tab), `src/client/IssuePane.tsx` (list/detail/empty/no-repo states), `src/client/format.ts`. Tests: `tests/unit/server/{repo,github-issue,cache,rpc}.test.ts`, `tests/unit/client/{format,issue-store}.test.ts`.

## R2 — dsh-ghl: client rendering + workspace context availability

- **"No repo" text** (`src/client/IssuePane.tsx:28-34`): rendered when local `repo === null`; driven purely by `state.repo` written from the `detectRepo` payload (`src/client/index.ts:112-113`) — a *successful* `detectRepo` returning `repo: null`. Not driven by any RPC failure; there is no store "error" state (`src/client/index.ts:84`: state = `{ repo, issues, selected }` only).
- **RPC failure handling**: single unwrap point `callRpc` (`src/client/index.ts:65-70`) — on `ok:false` it `throw new Error(result.error.message)`; `error.code` and `error.details` are **dropped**. Call sites `refresh()` (`index.ts:111-117`) and `select()` (`index.ts:120-124`) are invoked fire-and-forget (`void refresh()` at `index.ts:170` and `IssuePane.tsx:24`, `void select(...)` at `IssuePane.tsx:72`) with **no catch** → an RPC failure becomes an **unhandled promise rejection**; `publish()` never runs, store keeps last state. A rate-limit error therefore never reaches the UI: the pane silently degrades to the "No issues" empty branch (`IssuePane.tsx:54-58`). Client unit tests only feed successful canned responses (`tests/unit/client/issue-store.test.ts`).
- **Client flow**: on tab open / plugin apply → `refresh()` → `detectRepo` first, then `listIssues` only if repo found (short-circuit at `index.ts:115`). Row click → `getIssue` → `select()`. `back()` is local-only.
- **Workspace context on the host: none.**
  - `src/index.ts:16`: `export const inject: string[] = []`; `apply` reads only `webServer` via nested `ctx.inject(['webServer'], …)` (`index.ts:33-54`).
  - RPC wire carries no path/workspace field (`src/rpc.ts:55` `ClientRequest = { type, rpcId, method, payload }`; payloads are `{}` / `{ number }`); handler is a raw `webServer` prefix route seeing only `req`/`res` (`src/rpc.ts:24-29, 45-52`).
  - `gitRemoteUrl()` (`src/repo.ts:16-23`) shells out with **no cwd argument** → uses the dsh host process CWD. This is the leading root cause of `repo: null`: the host process is not running in the workspace directory.
  - **Existing dsh seam (unused by ghl):** `ctx.workspaceRegistry` (`dsh/packages/workspace/workspace/src/index.ts:113-116`) exposes `list(): Workspace[]`, each `Workspace` has `path: string` (canonical directory, `dsh/packages/workspace/workspace/src/types.ts:63-72`) + `sessionIds`. A host plugin can inject it; ghl does not.
  - The raw webServer route handler signature is `(req: IncomingMessage, res: ServerResponse)` (`dsh/packages/host/webserver/src/index.ts:42-48, 166-173`) — no workspace there. The standard Connection RPC peer carries a cordis `Context`, but ghl bypasses the `connection` channel (broken host-side on 0.2.0-rc.2 — the documented workaround in `src/index.ts:42-50`).

## R3 — packages/dsh-model-settings: debug-logging pattern (reference)

- **Mechanism**: home-grown gated logger `src/log.ts` (19 lines): `dbg = { log, info, warn, debug, error }` wrapping global `console`. Every level except `error` is gated on `process.env.DEBUG === '1'` (exact value — no globs); `error` is never gated. `TAG = '[model-settings]'` is prepended to every line so call sites don't repeat it.
- **Format**: `[model-settings]` + free-form `key=value` pairs in one interpolated string, or a short sentence + appended objects/Errors (e.g. `dbg.debug('fetchModels HTTP ' + response.status)`, `dbg.error('autofill: persist failed for "…":', err)`). Levels used in practice: `debug` (traces) and `error` (failures).
- **Placement**: (1) lifecycle/event handlers — `src/index.ts:288` logs every `settings/document-updated` event with all decision-relevant fields; (2) outbound HTTP — `src/probe.ts:89,97,100,109` traces URL+auth, status, body size, parsed count; (3) batch rounds — `src/autofill.ts:65-112` brackets `round start`/`round end`, per-route skips, persist failures. The RPC handler logs nothing (failures answered on the wire).
- **Client half**: does **not** log at all (no `console.` in `src/client/`).
- **One double-report site**: `src/index.ts:298-299` — `dbg.error(...)` + `ctx.logger.error(...)` (dsh's own context logger) on the top-level watcher failure, so it is visible through both channels even without `DEBUG=1`.
- **Tests**: `tests/unit/server/log.test.ts` — four cases: silent without `DEBUG=1`, tagged output with `DEBUG=1`, exact-value gating (`'0'`/`'*'`/name/`'true'` all disabled), always-loud `error`.
- **README**: `README.md:48-51` documents "Debugging" (quiet by default; `DEBUG=1` for trace output; errors always printed).
- **Replication recipe for dsh-ghl**: copy `log.ts` with `TAG = '[ghl]'`, import only in host modules that trace requests/lifecycle, mirror the four test cases in `tests/unit/server/log.test.ts`, add a README "Debugging" section.

## S1.1 — workspaceRegistry in dsh 0.2.0-rc.2 (Stage 1 deep research)

- **Version facts**: the `dsh/` symlink points to `/home/apkawa/source/deepseek-harness` at git tag `dsh-v0.2.0-rc.2` (commit `639ed01539`) — **exactly** the pinned e2e version, so the symlink source is authoritative. `.tmp/dsh-versions/0.2.0-rc.2` is the e2e throwaway *consumer project* (npm package, bundled `lib/` only — no source, no type declarations).
- **Answer: yes.** `ctx.workspaceRegistry` is a declared Context member in 0.2.0-rc.2:
  - declaration: `dsh/packages/workspace/workspace/src/index.ts:113-116` (`interface Context { workspaceRegistry: WorkspaceRegistry }`);
  - service: `WorkspaceRegistry extends Service` (`index.ts:170-194`), `list(): Workspace[]` (`index.ts:284-298`, synchronous, durable order), also `resolveByPath(path): Promise<Workspace | undefined>` (`index.ts:500`);
  - `Workspace.path: string` — canonical `fs.realpath` directory (`dsh/packages/workspace/workspace/src/types.ts:63-72`), plus `Workspace.id` (stable uuid).
- **Consumption pattern**: declare in the plugin's `inject` array, then read `ctx.<name>` directly (dsh convention: `ctx.get(name)` for optional services, `ctx.<name>` for declared injections).
- **In-repo precedent (e2e-verified on 0.2.0-rc.2):** `packages/dsh-global-queue`:
  - `src/index.ts:18` — `export const inject = ['agents', 'sessions', 'sessionPersistence', 'sessionProjections', 'workspaceRegistry', 'agentDefaultModel', 'agentPresets']`;
  - `src/index.ts:228` — `ctx.workspaceRegistry.create(workspacePath).then(…)`;
  - `src/index.ts:102-106` — **structural seam mirror** because the plugin does not depend on the dsh workspace package: `interface WorkspaceRegistrySeam { create(path: string, title?: string): Promise<WorkspaceSeam> }`, merged into `Context` at `src/index.ts:130` with the comment "The dsh 0.2.0 host provides these seams on plugin contexts, but this plugin does not depend on the dsh packages that type them, so these structural mirrors carry the reads."
  - e2e-verified: `E2E_DSH_VERSIONS = ['0.2.0-rc.2']` (`tests-helpers/e2e/dsh.ts:29`), `packages/dsh-global-queue/tests/e2e/acceptance.spec.ts:7`.
- **dsh-model-settings**: no workspace usage (host injects nothing top-level; client injects `['slots', 'connection', 'remote']`).
- **Recipe for dsh-ghl**: add `'workspaceRegistry'` to the `inject` export + a structural mirror (`list(): { readonly id: string; readonly path: string }[]`) — no dependency on the dsh workspace package.

## S1.2 — client workspace seams on dsh 0.2.0-rc.2 (Stage 1 deep research)

- **Client ctx**: Cordis itself is workspace-agnostic. The client-side `workspaces` service (`@deepseek-ai/dsh-api-workspace-controller`) augments `Context` with `workspaces: IWorkspaces` (`dsh/packages/api/workspace-controller/src/client/index.ts:33-38`); `IWorkspaces.list: WorkspaceSource` (`service.ts:46-49`); snapshot rows are `WorkspaceView { workspaceId, path, sessionIds, … }` (`types.ts:18-25`, `model.ts:30-38`). It is a live projection of the **host** registry via the `remote.workspace` follow stream.
- **No "current workspace" ctx member**; client session rows carry no `workspaceId` — the link is inverted (`WorkspaceView.sessionIds`).
- **Component world**: the standard `useWorkspaces` hook (`dsh/packages/client/ui-workspace/src/client/index.ts:67-71`); session-scoped slot entries receive `sessionId` + `useWorkspaces`.
- **Sibling precedent (dsh-global-queue)**: the client sends the workspace **path** in the RPC payload; the host **requires** it — `packages/dsh-global-queue/src/rpc.ts:113-122` (`bad-request` if not a non-empty string). Client derivation — `packages/dsh-global-queue/src/client/AddToQueue.tsx:40`: `props.useWorkspaces(state => state.items.find(w => w.sessionIds.includes(props.sessionId))?.path)`.
- **GUI app side**: no app-level workspace seam (`window.__DSH_BOOT__` is boot-manifest only).

## Decision (Stage 1) — workspace resolution, hybrid

1. `payload.workspacePath` (validated non-empty string) takes priority — the client sends it (Stage 4), conforming to the e2e-verified `dsh-global-queue` precedent.
2. Fallback (host): `workspaceRegistry.list()` → exactly 1 → its `path`; 0 → failure `no-workspace`; >1 → failure `ambiguous-workspace` (paths listed in the message).
3. All failures are transparent (code + message); git always runs in the resolved cwd.

## Stage 2–6 execution notes

- **Stage 2 (host detection)**: `gitRemoteUrl(cwd?)` adds a `.git`-root guard (`stat(cwd/.git)` — dir or file, so worktrees/submodules work) — without it, a plain dir *inside* a repo (like `.tmp/` scratch dirs) inherits the enclosing repo's origin via git's parent search; the guard narrows semantics to "the repo rooted at cwd", which matches the workspace use case. New pure functions `resolveWorkspacePath(payloadPath, workspaces)` and `detectRepo(getRemoteUrl, resolution)`; the old `detectRepo` contract is replaced. Composition root: `inject = ['workspaceRegistry']` + structural mirror `WorkspaceRegistrySeam { list(): readonly { path: string }[] }` (global-queue pattern); `RpcDeps.getRepo` is now `(payload: unknown) => Promise<DetectionResult>` (endpoint behavior unchanged until Stage 3).
- **Stage 3 (RPC transparency)**: detection failures pass through verbatim at all three endpoints via a `detectionFailure()` helper (`rpcFailure(code, message, {})`); the `no-repo` code is **gone** from the host (grep-clean). Consequential renames: pane testid `ghl-no-repo` → `ghl-missing-repo` (a `no-repo`-substring name would have tripped the grep gate); e2e pins updated in the same commit.
- **Stage 4 (client)**: `RpcError extends Error { code, details }` exported from `src/client/index.ts`; store gains `error: { code, message } | null` + `getError()`; `refresh`/`select` catch at the RPC boundary (`asRpcError(err)` structural guard — a non-`RpcError` `Error` without a string `code` is recorded as `internal`) and resolve instead of rejecting. `IssuePane` renders the error branch (testid `ghl-error`, message + code) with highest precedence; `ghl-missing-repo` remains only for the initial no-error state. No React component-test infra exists in the repo (no `@testing-library/react`, vitest `environment: 'node'`) — none added (KISS); pane covered by store tests + e2e lane. **Workspace path**: the pane seat `sidebar.right.pane.tab` is `kind: 'keyed'`, `scope: 'session'` (`dsh/packages/extensions/cordis-client-runner/src/client/slot-catalog.ts:3092`) — the session-scoped dispatcher hands `sessionId` (and a standard `useWorkspaces`) as props; the client `apply` reads the `workspaces` seam (structural mirror `WorkspacesFace`, no `declare module` on the client half — matching global-queue, whose `declare module` is host-side only) and injects a `useWorkspaces` selector hook via the seat's inject face; the pane derives `items.find(w => w.sessionIds.includes(sessionId))?.path` and passes it to `refresh(path?)`/`select(n, path?)` → payload `{ workspacePath }` only for a non-empty string. Note: the pane therefore receives `useWorkspaces` from both the inject face and the seat standard props — both bound to the same observable, identical behavior; accepted as-is to mirror global-queue's "obtain → inject" flow.
- **Stage 5 (logging)**: `src/log.ts` mirrors `dsh-model-settings/src/log.ts` with `TAG = '[ghl]'`; placements: `repo.ts` (resolution branches, git result, detection outcome — `dbg.debug`), `issues.ts` (`request` GET + `dbg.error` on 403/429/404/other), `rpc.ts` (`dbg.error` in `rpcFailure` — covers the internal catch, which funnels through it), `cache.ts` (`dbg.warn` on budget exhaustion only). Side effect: `tsconfig.client.json` needed `"types": ["node"]` (was `[]`) because the client program type-imports `../issues.ts`, which now value-imports `log.ts` (`process` reference) — typecheck-only, the import is erased from the client bundle.
- **Stage 6 (verification + docs)**: unit 100/100 + typecheck green. **E2e boot smoke caught a stale `lib/` build** — dsh loads the package's `lib/` (built Oct 8, pre-change contract); `pnpm build` fixed it (`lib/` is git-ignored). With per-workspace resolution, a fresh throwaway home registers **zero** workspaces, so payload-less e2e requests fail `no-workspace` before git detection — the RPC e2e pins now send `workspacePath: handle.root` (the git-init'ed, no-origin home) to exercise the `no-remote` path of the new contract. Final e2e: 6/6 green on 0.2.0-rc.2 (boot 2/2, rpc 4/4).
